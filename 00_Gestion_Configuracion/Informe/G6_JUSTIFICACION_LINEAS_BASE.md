# Justificación de los momentos definidos para establecer Líneas Base

Para la organización del repositorio se considera Línea Base a una versión identificada, revisada y formalmente aprobada de un conjunto de ítems de configuración. Esta versión funciona como referencia estable para continuar el trabajo y permite conocer con precisión qué archivos integraban el proyecto en un momento determinado. Por ese motivo, una Línea Base no se genera ante cada modificación o commit, sino únicamente cuando se alcanza un hito relevante que requiere trazabilidad, posibilidad de recuperación y control sobre los cambios posteriores.

La primera Línea Base se establece una vez aprobados el árbol de carpetas, el README, el inventario operativo incluido en el propio README y las reglas de nombrado. Este momento fue seleccionado porque dichos elementos definen la forma en que todo el grupo incorporará y administrará la información. Al fijarlos antes de cargar el resto del material, se reduce el riesgo de que aparezcan archivos duplicados, ubicaciones incorrectas o criterios diferentes entre los integrantes. Esta Línea Base inicial constituye, por lo tanto, el punto de partida común para el repositorio.

Los siguientes hitos seleccionados son las fechas de cierre o subida de cada Trabajo Práctico evaluable. Cada Línea Base congela el commit que representa la versión efectivamente entregada del TP correspondiente. Las primeras referencias son `LB_TP01_final`, `LB_TP02_final` y `LB_TP03_final`. Esta decisión permite recuperar el estado exacto de cada entrega, relacionarlo con su fecha real y comparar su evolución sin depender de la fecha de creación posterior de la etiqueta.

No se establecen Líneas Base independientes por unidad, parcial o componente de código. Esos elementos se incorporan a la Línea Base del Trabajo Práctico correspondiente. Cuando una entrega histórica se encuentra en una rama remota distinta de `main`, la ficha debe registrar la rama y cualquier diferencia conocida respecto de otras ramas antes de crear la etiqueta anotada.

Por último, se establece una Línea Base final al concluir las actividades de la materia y después de realizar una revisión integral del repositorio. Esta versión reúne los ítems vigentes, el inventario actualizado, los registros de cambios y las evidencias de las entregas. Su finalidad es representar el estado definitivo del trabajo del grupo y conservar una referencia completa para futuras consultas o auditorías.

En todos los casos, el establecimiento de una Línea Base exige un alcance verificable, ubicación conocida y trazabilidad en `00_Gestion_Configuracion/Inventario_IC/G6_INVENTARIO_IC.md` y en el registro correspondiente. Una Línea Base nueva requiere revisión del responsable y de al menos otro integrante. Una reconstrucción histórica se apoya en la evidencia objetiva del commit de entrega y documenta expresamente la fecha en que se realizó la reconstrucción. La Línea Base se identifica mediante una etiqueta anotada de Git asociada a un commit específico. Una vez corregida y publicada, esa etiqueta no se elimina ni se reasigna. Cualquier modificación posterior debe tramitarse mediante el control de cambios y, si altera la referencia aprobada, debe originar una nueva revisión sin mover la etiqueta original.
